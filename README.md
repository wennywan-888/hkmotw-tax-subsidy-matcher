## 核心设计

### 一、政策数据与代码彻底分离

`src/` 里的代码**不含任何政策金额和条件**。所有政策都在 `data/policies.json`。
政策每年变，改数据不改代码。

### 二、机器发现变化，人确认发版

```
定时巡检官方源 → 发现差异 → 自动开 PR（附原文引句）
                                    ↓
                        你打开原文核对 → 合并 = 发版
                                    ↓
                              关闭 PR = 数据不变
```

**巡检脚本绝不自动改政策数据。** 它甚至不猜「变成了多少」——
猜错就是把错误金额推上线，用户拿着去申请会白跑。
它只标记「这条待核实」，让前台显示提示，具体新值由人填。

### 三、三层失效兜底

1. 数据文件坏了 → 自动加载上一个正常版本，不白屏
2. 某条超 180 天未核实 → 前台显示「信息可能过时」
3. 连备份都读不到 → 显示友好提示并引导用户去官网 / 打 12333

第 2 条是刻意设计的：上线几个月后维护频率必然下降，
这一层在你偷懒时替你向用户承认「我可能过时了」。

## 日常维护

### 云端（推荐）

什么都不用做。Actions 按下面频率自动巡检，有变更就开 PR，你在手机上审批。

| 时间 | 范围 | 为什么 |
|---|---|---|
| 每周一 | 申报窗口 | 唯一「错过就等一年」的东西 |
| 每月 1 日 | 全量 | 常规体检 |
| 每季度末 | 链接有效性 | 政府网站改版频繁 |
| 1/2、3/15 | 加密 | 个税补贴 1/1 开放、3/31 截止 |
| 7/25、8/5 | 加密 | 前海十二条 7 月底发指南、8 月初开窗 |

想临时手动跑：仓库 → Actions → 政策巡检 → Run workflow，可选范围和指定政策。

### 本地（临时核查一条）

```bash
python3 tools/patrol.py --only qh-employ-001   # 只查一条
python3 tools/confirm.py --list                # 看待确认项
python3 tools/confirm.py                       # 逐条确认
```

详见 `docs/维护手册.md`。

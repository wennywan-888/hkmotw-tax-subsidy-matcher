# 上线到 GitHub · 操作步骤

代码和工作流都已就绪。你只需要照这份做一遍，之后就全自动了。

预计 10 分钟。

---

## 第 1 步：装 gh 命令行工具

你机器上还没有。终端里跑：

```bash
brew install gh
```

没装 Homebrew 的话，去 https://cli.github.com 下载安装包也行。

> 也可以完全不装 gh，用网页操作（第 3 步有替代方案）。
> 但装了之后建仓和推代码一条命令搞定，省事。

---

## 第 2 步：登录 GitHub

```bash
gh auth login
```

按提示选：
- `GitHub.com`
- `HTTPS`
- `Login with a web browser` → 复制显示的验证码 → 浏览器里粘贴授权

---

## 第 3 步：建仓库并推代码

进项目目录：

```bash
cd /Users/wennywan/WorkBuddy/2026-08-17-10-05-21/hkmo-subsidy
```

### 方式 A：用 gh（推荐）

```bash
gh repo create hkmo-subsidy-matcher --private --source=. --remote=origin --push
```

一条命令搞定：建私有仓库 + 关联 + 推送。

> 想直接公开的话把 `--private` 换成 `--public`。
> 建议先私有，等政策核实完、第 6 轮合规做完再公开。

### 方式 B：网页操作

1. 打开 https://github.com/new
2. Repository name 填 `hkmo-subsidy-matcher`，选 Private，**不要**勾选任何初始化选项
3. 建好后回终端：

```bash
git remote add origin https://github.com/你的用户名/hkmo-subsidy-matcher.git
git branch -M main
git push -u origin main
```

---

## 第 4 步：开启 Actions 的写权限

Actions 需要权限才能推分支、开 PR、开 issue。

仓库页面 → **Settings** → 左侧 **Actions** → **General** → 拉到底部
**Workflow permissions**：

- 选 **Read and write permissions**
- 勾上 **Allow GitHub Actions to create and approve pull requests**
- 点 Save

**这步不做，巡检跑完开不了 PR。**

---

## 第 5 步：建两个标签

工作流会给 PR 和 issue 打标签，标签不存在会报错。

仓库页面 → **Issues** → **Labels** → **New label**，建这两个：

| 名称 | 建议颜色 | 用途 |
|---|---|---|
| `政策巡检` | 蓝色 | 巡检自动开的 PR |
| `巡检异常` | 红色 | 巡检失败通知 |

用 gh 也行：

```bash
gh label create "政策巡检" --color 0052d9 --description "自动巡检发现政策变更"
gh label create "巡检异常" --color d32029 --description "巡检失败或被安全阀中止"
```

---

## 第 6 步：开启 GitHub Pages（拿到网址）

仓库页面 → **Settings** → 左侧 **Pages** → **Build and deployment**：

- **Source** 选 **GitHub Actions**（不要选 Deploy from a branch）

然后触发部署：

```bash
git commit --allow-empty -m "触发首次部署" && git push
```

或者 Actions → **部署到 Pages** → Run workflow。

跑完在该次运行的 **Summary** 里会显示访问地址，形如
`https://你的用户名.github.io/hkmo-subsidy-matcher/`

> **私有仓库要用 Pages 需要 GitHub Pro。** 免费账号想用就得改成 Public
> （Settings → 底部 Danger Zone → Change visibility）。
>
> 政策数据都是公开信息，公开仓库没有敏感信息风险。
> 但如果你想等第 6 轮合规做完再公开，可以先跳过这步。

### 验收标准

**手机关掉 WiFi、用流量打开这个网址**，确认：
- 顶部显示「政策数据 v1.0.0，截至 2026-08-17　共 19 项政策」
- 点任一示例按钮能出结果卡片
- 卡片里的官方来源链接能点开

关 WiFi 是为了确认它真在公网上，不是只在你电脑上跑。

---

## 第 7 步：手动跑一次巡检，验证通路

仓库页面 → **Actions** → 左侧 **政策巡检** → 右上 **Run workflow**：
- `scope` 选 `window`（快，只查申报窗口）
- `only` 留空
- 点绿色 **Run workflow**

等一两分钟，进去看运行结果：

**看什么：**
- 每个 step 是否绿勾
- 点开 **Summary**，应该能看到巡检报告
- 如果有变更，应该自动开了一个 PR（去 Pull requests 看）

**常见问题：**

| 现象 | 原因 | 解决 |
|---|---|---|
| `Resource not accessible by integration` | 第 4 步没做 | 回去开写权限 |
| `could not add label` | 第 5 步没做 | 建标签 |
| 大量「链接失效」 | GitHub 服务器在境外，访问国内政府站点可能受限 | 见下面「如果云端抓不动」 |

## 如果云端抓不动国内政府站点

GitHub Actions 的机器在境外，访问 `sz.gov.cn` 这类站点**可能不稳定**。
如果第 6 步发现大面积「链接失效」，但你本地 curl 明明能通，说明就是这个问题。

三个应对方案，按推荐顺序：

### 方案 1：本地跑巡检，云端只做校验和部署

最简单。你每月手动跑一次：

```bash
py tools/patrol.py
py tools/confirm.py
git add -A && git commit -m "政策数据更新" && git push
```

云端保留 `validate.yml`（PR 校验）和之后的部署工作流，
把 `patrol.yml` 的定时触发注释掉，只留手动触发备用。

### 方案 2：换成国内的 CI

腾讯云 CNB、Coding 这些国内平台的机器在境内，抓政府站点没问题。
代码不用改，只需把 `.github/workflows/` 里的工作流翻译成对应平台的配置。

### 方案 3：自己的机器跑定时任务

如果你有一台常开的机器（或者树莓派、NAS），配个 crontab：

```bash
# 每周一 9 点查窗口
0 9 * * 1 cd /path/to/hkmo-subsidy && python3 tools/patrol.py --scope window
```

## 之后的日常

配好之后你不用再碰终端：

1. Actions 按时自动巡检
2. 发现变更自动开 PR，GitHub 手机 App 会推通知
3. 你点开 PR，看官方链接核对原文
4. 合并 = 采纳，关闭 = 驳回

详细审批流程见 `docs/维护手册.md` 第一部分。
